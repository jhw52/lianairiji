## 0. 一句话定义

一个**私有部署、仅两人可用**的恋爱记录站：网站是壳，数据是核，二者彻底分离。两人用同一套后台，**谁改谁上传，对方几秒内就能看到**。核心模块：时间轴 · 相册（EXIF 自动归日 + AI 自动分类）· 经期与亲密日历（含预测）· 纪念日 · 心愿清单 · 悄悄话。左侧是可拖拽缩放、可折叠的侧边栏。视觉是奶油胶片风。

### 目标
| # | 目标 | 判定方式 |

## 3. 权限与账号

| 角色 | 权限 |
|---|---|
| 未登录 | 只能看到登录页 |
| 双人账号（owner / partner） | 全部内容的读 + 写 + 删（含对方创建的） |
| 系统管理员 | `owner` 兼任：改站点设置、AI 配置、导出备份、重置密码 |

规则：
- 账号数上限硬编码为 2；`/api/auth/register` 仅在初始化时开放一次，之后 403。
- 首次启动走**初始化向导**：设置站点名、两人昵称、两个密码、在一起的日子，生成 `.initialized` 标记。
- 密码 bcrypt(cost 12)；会话 = httpOnly + SameSite=Lax + Secure(https) 的 cookie，有效期 30 天，服务端存 token 哈希，可单端下线。
- 登录失败：同 IP 5 次/5 分钟 → 锁 15 分钟；记录审计日志。
- 忘记密码：只能服务器 CLI `npm run reset-password` 重置（不开放邮箱找回）。

## 4. 部署形态（私有化）

### 4.1 三种可选落点（❓需你选一种）

| 方案 | 访问方式 | 成本 | 国内稳定性 | 备案 |
|---|---|---|---|---|
| **A. 家里电脑/NAS 常开 + Tailscale** | 设备装 Tailscale，用内网域名访问 | 0 元 | 高（P2P 直连） | 不需要 |
| **B. 国内轻量云服务器 + 域名** | `https://love.你的域名` | 约 100–200 元/年 + 域名 | 最高 | **需要备案** |
| **C. 国内轻量云服务器 + IP:端口** | `http://1.2.3.4:8443` | 约 100 元/年 | 最高 | **不需要**（非 80/443） |

推荐：**先 A 跑起来用**（零成本、零备案、数据在自己手里），用顺了再迁 B。

### 4.2 运行结构

```
docker-compose.yml
├── app   (Node + 前端构建产物，无状态，只读镜像)
└── caddy (反向代理 + 自动 HTTPS，可选)
        └── 卷: ./data  →  /data
```

- `docker compose up -d` 即完成部署；更新 = 拉新镜像 `up -d`，数据卷不动。
- 环境变量：`APP_SECRET`（加密 AI Key / 签名 cookie）、`PORT`、`DATA_DIR`、`TZ=Asia/Shanghai`、`TRUST_PROXY`。
- 资源占用目标：空闲 < 150MB 内存，镜像 < 400MB。

### 4.3 数据目录（备份即拷这一份）

```
data/
├── app.db            SQLite（WAL 模式，含 -wal/-shm）
├── media/
│   ├── orig/2026/10/<sha256>.jpg   原图（仅本人可下载）
│   ├── large/...webp               展示用 2000px
│   ├── thumb/...webp               列表用 480px
│   └── micro/...webp               64px 占位图
├── backups/          每日 03:00 自动快照（保留 7 天 + 每周 1 份，保留 8 周）
└── .initialized
```

### 4.4 备份 / 恢复 / 迁移
- 自动：每日 `VACUUM INTO` 快照 + 媒体增量清单。
- 手动：后台「设置 → 数据」一键导出 `backup-YYYYMMDD.zip`（db + 媒体 + JSON 清单）。
- 迁移：新机器 `docker compose up` 后上传 zip 自动导入，或直接替换 `data/` 目录。
- 恢复演练入口：导入前校验 sha256 与文件数，失败回滚。

## 5. 系统架构（网站与数据完全分隔）

```
浏览器 SPA (只读静态产物)
   │  HTTPS / JSON + SSE
   ▼
Fastify API（无状态，可多实例）
   ├── 业务层（zod 校验 / 权限 / 乐观锁）
   ├── 任务层（AI 分类队列，进程内串行、并发 2）
   └── 存储层  ──►  /data 卷（SQLite + 媒体文件）
```

分离的具体含义（验收时逐条验证）：
1. 前端构建产物里**不含任何业务数据**，换一套前端也能直接用 API。
2. 服务端**不把数据写进代码目录**，只写 `DATA_DIR`。
3. 删除 `data/` → 站点回到"待初始化"空状态，代码无需改动。
4. 打包 `data/` → 在任何一台机器上 `docker compose up` 即可 100% 还原（含照片原图）。

### 5.1 实时同步
- `GET /api/events`（SSE）：服务端每次写操作后 `bump(version)` 并向所有连接推送
  `event: changed` / `data: {"version":123,"topics":["media","albums"],"actor":"她"}`。
- 前端用 TanStack Query，收到事件后按 topic `invalidateQueries`，2 秒内完成刷新。
- 心跳 25s；断线指数退避重连（1s→30s）；`Last-Event-ID` 补发最近 100 条事件。
- 兜底：SSE 不可用时降级为 20s 轮询 `GET /api/version`（带 ETag）。
- 在线状态：`GET /api/presence` 显示"她在线"，仅提示，不做协同光标。

### 5.2 并发与冲突
- 所有可编辑实体带 `rev INTEGER`；`PATCH` 必须带 `If-Match: <rev>`，不匹配返回 `409 CONFLICT` + 最新实体。
- 前端弹「内容已被她修改，已为你刷新」，保留用户未提交的草稿到 localStorage。
- 删除为软删除（`deleted_at`），30 天内可在「回收站」恢复。

## 8. API 概览

> 统一前缀 `/api`；统一返回 `{ data }` 或 `{ error: { code, message, details } }`；
> 错误码：`UNAUTHORIZED / FORBIDDEN / VALIDATION / CONFLICT / NOT_FOUND / RATE_LIMITED / AI_FAILED / INTERNAL`。

**认证**：`POST /auth/login` `POST /auth/logout` `GET /auth/me` `POST /auth/password`
**引导**：`GET /bootstrap`（me + settings + 版本 + 计数）`GET /events`(SSE) `GET /version` `GET /presence`
**媒体**：`POST /media`(multipart 批量≤10) `GET /media?day&album&tag&q&cursor` `GET /media/:id`
`PATCH /media/:id` `DELETE /media/:id` `GET /media/:id/file?size=thumb|large|orig` `POST /media/bulk`
**相册**：`GET|POST|PATCH|DELETE /albums` `POST /albums/:id/media` `DELETE /albums/:id/media/:mediaId`
**分类**：`POST /media/:id/reclassify` `GET /jobs` `POST /jobs/:id/retry` `GET|PUT /ai/config` `POST /ai/test`
**标签/人物**：`GET|POST|PATCH|DELETE /tags`、`/persons`
**内容**：`/moments` `/letters` `/anniversaries` `/todos` `/messages`（均 CRUD）
**日历**：`GET|POST|PATCH|DELETE /cycles` `GET /cycles/summary`（预测）`GET|POST|PATCH|DELETE /intimacy`
**系统**：`GET|PUT /settings` `GET /search?q=` `GET /export` `POST /import` `GET /stats`

## 9. 功能规格

### 9.1 左侧侧边栏（贯穿全站）

| 项 | 规则 |
|---|---|
| 展开宽度 | 默认 248px，可拖拽 200–360px |
| 折叠 | 点击按钮或双击拖拽条 → 64px 图标栏；再点展开回上次宽度 |
| 持久化 | 宽度/折叠态存 `localStorage`，跟随设备 |
| 拖拽 | 手柄 6px 宽，悬停变主题色；拖拽时实时预览，松手落库 |
| 当前项 | 左侧 3px 主色竖条 + 淡色背景 + 图标实心 |
| 内容 | 首页 / 时间轴 / 相册 / 日历 / 纪念日 / 清单 / 悄悄话 / 设置（底部） |
| 底部 | 同步状态点（已连接/重连中）、当前用户头像与退出 |
| 移动端 | <768px 自动收起为抽屉 + 遮罩，手势左滑呼出 |
| 动画 | 宽度 200ms `cubic-bezier(.4,0,.2,1)`；`prefers-reduced-motion` 时关闭 |

### 9.2 首页
在一起第 N 天 N 时（实时秒级跳动）+ 主视觉合照 + 一句题词 + 最近 6 张照片 + 快捷入口（上传照片 / 写日记 / 记日历）。
空数据时显示引导卡片，不显示破图。

### 9.3 时间轴
按年月分组；卡片含日期、标题、Markdown 正文、九宫格图、地点；支持标签筛选与搜索；无限滚动分页（每页 20）。

### 9.4 相册

**上传**：拖拽或点选，多选（单次 ≤10 张，单张 ≤50MB，类型 jpg/jpeg/png/webp/heic/gif/mp4/mov）→ 前端读文件 `lastModified` 作为兜底日期 → 批量上传带进度 → 服务端计算 sha256 去重 → sharp 转码三档 → 写库 → 触发 AI 分类。

**拍摄日期识别**（优先级）：
1. EXIF `DateTimeOriginal`（含时区偏移，按 `Asia/Shanghai` 归日）
2. EXIF `DateTimeDigitized` / `DateTime`
3. 视频容器创建时间
4. 浏览器 `lastModified`
5. 上传时间
命中 1–3 标 `exif`；命中 4–5 标 `mtime`，卡片上显示「日期待确认」可一键改。

**视图**：
- 按天（默认）：`2026年10月29日 · 12 张` 分组，日期侧边滚动锚点
- 自动合集：按风格 / 场景 / 人物聚合（来自 AI 标签）
- 手动相册：用户自建，可拖拽排序
- 全部 / 收藏 / 最近上传
- 瀑布流（列宽 220–280 自适应），懒加载 + 模糊占位图

**灯箱**：键盘 ← → / Esc，手势滑动，显示拍摄时间/地点/AI 标签/文件信息，可编辑说明、加入相册、收藏、删除、下载原图。

**批量**：多选后加入相册、打标签、收藏、删除。

### 9.5 AI 自动分类

**触发**：媒体入库且 `ai_status=pending` 时入队。同一 `sha256` 只分类一次（重复上传不重复计费）。
**队列**：进程内 worker，并发 2，单张超时 90s，失败退避重试 3 次（5s/20s/60s），最终 `failed` 可在后台一键重试。任务状态经 SSE 实时更新。
**输入**：默认发送 1024px JPEG（q80）以省 token；可配置是否发送原图。
**接口**：OpenAI 兼容 `POST {base_url}/chat/completions`，`messages` 含 `image_url`（data URI）。

**提示词模板（固定）**：

```
你是照片整理助手。分析这张照片，只输出一个 JSON 对象，不要任何解释或 Markdown 代码块。

{
  "caption": "一句话描述，30 字以内，中文",
  "scene": ["最多3个，从 旅行/日常/约会/美食/居家/户外/夜景/室内/海边/山野/城市/节日/运动/宠物/聚会 中选，可自拟"],
  "style": ["最多2个，如 胶片/日系/复古/明亮/暗调/柔光/纪实/唯美/港风"],
  "mood": "一个词，如 开心/温柔/安静/热闹/浪漫/疲惫/惬意",
  "people": [{"name": "人物名或 未知", "confidence": 0.0}],
  "location_guess": "可能地点，没有填 null"
}

若提供了人物参考照，请判断照片中是否出现该人物，name 用参考照对应名字，confidence 取 0~1。
```

**结果落地**：`caption` 写 `media.caption`（若用户已手写则不覆盖），标签写入 `tags/media_tags`，人物写 `person_media` 关联（置信度 <0.6 仅建议不自动关联）。自动生成「按风格」「按人物」虚拟相册。
**失败处理**：不影响浏览；卡片角标「待分类」；后台任务页可见原因（未配置 Key / 模型不支持图片 / 超时 / 限流）。
**配置项**：开关、base_url、api_key（加密）、model、是否支持图片、并发、每日调用上限、成本估算。
**⚠️ 说明**：DeepSeek 官方文本接口目前不接受图片输入。若你填的模型不支持视觉，分类会统一失败并明确提示，届时换任一 OpenAI 兼容的多模态模型即可（接口形态不变）。

**人物识别口径**（❓请确认）：
- 方案 1（推荐）：先建「人物档案」上传 1–3 张参考照，分类时把参考照一并送模型比对；
- 方案 2：不做人脸，只按"照片里有没有人/几个人"粗分；
- 方案 3：本地人脸聚类（离线、免费、准，但需额外部署 Python 模型）。

### 9.6 日历（经期 + 亲密）

**月历视图**：左侧大日历，右侧统计与图例。

- 经期：实心条覆盖连续日期（进行中显示到今日 + 虚线）；颜色 #C98474。
- 亲密：当天显示小圆点/icon，不显示细节；点击查看。
- 预测：下次经期用虚线框 + 「预计」角标；易孕期浅色底。
- 点击任意日期 → 底部弹层「记经期 / 记亲密 / 查看」。
- 经期支持只填开始（进行中），后补结束；自动校验不与已有区间重叠。

**亲密记录字段**：日期、时间、类型（可多选标签：亲密/爱爱/其他，标签可自定义）、防护（是/否/未记录）、心情、备注。

**预测算法**（服务端 `GET /cycles/summary`）：

```
samples = 相邻两次经期开始日期的间隔，仅保留 15 ≤ gap ≤ 60 天的样本
取最近 6 个样本：
  avg_cycle   = 中位数(samples)
  sd          = 样本标准差（<2 个样本时置空）
  avg_length  = 中位数(最近 6 次经期天数)
next_start    = last_start + avg_cycle
range         = [next_start - max(sd,1), next_start + max(sd,1)]
ovulation     ≈ next_start - 14
fertile       = [ovulation - 5, ovulation + 1]
```

- 样本 < 2：用默认 28 天/5 天，界面标「数据不足，仅供参考」。
- 所有预测卡片固定显示：「预测基于历史数据，仅供参考，不能作为避孕或医疗依据」。
- 统计卡片：平均周期、最短/最长、平均经期天数、下一次预计日期与倒计时、已记录次数。

**隐私**：日历页默认需要登录；设置里可开「私密板块二次验证」（进入前再输一次密码）。对外标题统一为「日历」。

### 9.7 纪念日
卡片列表 + 倒计时（下次还有 N 天）/ 已过 N 天；支持每年、每月、一次性；日期临近 7 天内高亮。

### 9.8 心愿清单
分类（旅行/美食/体验/礼物/其他），勾选打卡带时间戳，顶部进度条 `已完成 12/100`。

### 9.9 悄悄话
双人留言墙，按时间倒序，显示作者头像色标，可标记已读；支持"仅自己可见"草稿。

### 9.10 设置

### 9.11 状态设计

## 11. 安全与隐私

- 全站 `noindex`、`robots.txt` 拒绝全部、不发 Referer 给外站。
- 零外部请求：无 Google Fonts、无 CDN、无埋点；CSP 仅允许 `'self'`。
- 上传：类型白名单 + 服务端重编码（防伪装脚本）+ 文件名不落用户输入 + 存储路径按 sha256。
- 防护：CSRF 用 SameSite + 同源校验；参数全部 zod；SQL 全参数化；路径穿越校验。
- 限流：登录 5/5min，上传 60/h，AI 手动重试 20/h。
- 日志脱敏：不记录密码、cookie、AI Key；审计日志保留 90 天。
- 媒体下载：`/media/:id/file` 校验会话，禁止直接目录列举；`orig` 需登录。
